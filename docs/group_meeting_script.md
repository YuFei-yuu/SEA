## 开场白（1 分钟）

各位老师、同学大家好，我本周汇报的主题是"Motion-Aware SEA-Nav —— 面向复杂动态障碍物环境的四足机器人安全导航"。

这个工作的起点是开源项目 SEA-Nav，它是一个基于强化学习的四足机器人导航框架。导师给我的任务是：在 SEA-Nav 的基础上，调研前沿研究的方法，把它拓展到复杂障碍物环境下的动态避障导航。

本周我完成了五条工作主线：文献调研、环境重构、安全层扩展、训练诊断和奖励函数修复。下面我按照"研究问题 → 调研文献 → 归纳方法 → 改进项目 → 发现问题 → 解决问题"的学术研究思路，向大家汇报整个过程。

## 第一章：研究背景与问题定义（2-3 分钟）

请大家看这一页的架构图。

SEA-Nav 原始框架的核心是三个东西：PPO 训练的高层导航策略、LSE-CBF 安全层、以及 ACSI 碰撞状态自适应初始化。它的导航观测以本体状态、41 条射线扫描和目标方向为主，叠 10 帧历史形成高维历史观测。动作是高层速度命令 [vx, vy, yaw_rate]，经过 CBF 安全层投影后，再通过低通滤波和 PD 控制器驱动关节。

这个框架在静态密集障碍物中表现很好。但如果我们把问题推进到动态障碍物环境，它的架构存在四个明确的能力边界。

第一，观测层面：射线融合只是取静态射线和动态射线的最小值，也就是说它只知道"某个方向上有东西挡着"，但不知道这个东西是静止的还是正在靠近的。没有速度信息、没有运动方向、没有未来轨迹。

第二，安全层：SEA-Nav 里 alpha 由网络输出，但它主要基于当前历史观测学习一个通用安全调节，缺少面向 dynamic token 的显式速度条件化。也就是说，前面是静止箱子还是快速冲过来的障碍物，安全层并没有单独建模"相对速度会改变未来风险"这一事实。

第三，编码层面：MLP 展平向量把所有信息混在一起，无法建模障碍物之间的空间关系——比如你左边有个障碍物在靠近，右边也有一个在靠近，它们之间的交互影响，MLP 是看不出来的。

第四，训练策略：ACSI 是在真的撞上了之后才回放碰撞前的状态。但动态避障的场景里，很多时候你没撞上但已经很危险了，这种"差点撞上"的状态同样有很高的训练价值。

所以我把核心研究问题凝练成一句话：**如何将 SEA-Nav 从静态环境扩展到复杂多动态障碍物环境，同时保持安全性、训练稳定性和可扩展性？**

这个问题我分解成四个子问题：感知层面，观测中怎么显式编码运动趋势？安全层面，CBF 怎么从静态距离约束升级为速度感知的约束？行为层面，奖励函数怎么引导策略学会从障碍物后方通过的让行策略？训练层面，怎么让 PPO 在复杂动态场景中拿到有效的训练样本？

这四个子问题构成了本周全部工作的组织框架。

## 第二章：文献调研（8-10 分钟）

### 第一篇：Agile But Safe（RSS 2024）

这是 12 篇里第一篇要重点讲的。它来自 CMU 和 ETH，发表在 RSS 2024，硬件平台是宇树 Go1 四足——跟我们项目用的 Go2 是同系列，仿真栈也是 Isaac Gym，技术迁移路径非常清晰。

它的核心方法是双策略框架。一个敏捷策略负责高速导航，最高跑到 3.1 米每秒。一个恢复策略在碰撞风险升高时接管控制。但真正巧妙的地方不在有两个策略——而在于**策略切换不由硬编码规则决定，而是由一个学习的 Reach-Avoid 值网络来判决**。

这个 RA 值网络做什么呢？它学习预测"从当前状态出发，如果我继续用敏捷策略，未来多久会撞上"。这本质上就是一个从数据中学习的安全证书。它比我们手工设计 CBF 更灵活——CBF 需要你预设屏障函数的形式，比如距离平方减去安全距离平方，但这种形式在面对复杂动态场景时不一定是最优的。RA 值网络直接从数据中学哪些状态组合是危险的，不需要预设函数形式——这是安全性保障从"解析构造"到"数据驱动"的一次范式转换。

另外这篇文章还有几个实用的设计：射线预测网络把深度图压缩成 11 条稀疏射线，比我们的 41 条更少，适合机载部署。它在真实 Go1 上验证了极端鲁棒性——12 公斤负载等于自重、雪地、外部撞击。

那对我们 SEA-Nav 的启发是什么呢？第一，SEA-Nav 已经有 CBF 安全层了，但这个 CBF 只能看当前时刻，无法预测"未来三步会不会撞"。RA 值网络的思想提示我们，可以在 CBF 之上训练一个辅助值网络，用来动态调节安全裕度——障碍物快速靠近时收紧，远离时放松。第二，Go1 和 Go2 的硬件相似性说明从仿真到实机的路径是可行的。第三，41 条射线对机载部署可能偏多，后续可考虑蒸馏优化。

### 第二篇：Online CBF for Multi-Agent Navigation（MRS 2023）

这篇来自剑桥大学，发表在 MRS 2023。它处理的问题和 SEA-Nav 当前架构的痛点直接对应。

这篇文章的核心贡献是**系统论证了传统 CBF 固定参数或弱条件化参数的致命缺陷，然后提出了解决方案**。它说得很清楚：传统 CBF 用保守的参数，会导致 freezing robot problem——机器人为了安全永远在绕行，根本到不了目标。用激进的参数，在拥挤或高速场景下就会不安全。手工调参在不同的场景分布下无法泛化。SEA-Nav 当前虽然有 alpha head，但还没有专门针对动态障碍物相对速度、TTC 和局部交互关系做在线调度，正好对应了这个痛点。

那怎么解决呢？用 RL 学习一个 CBF 参数调度策略。RL 策略观察局部障碍物分布——周围有几个障碍物、它们的速度和方向——然后决定当前时刻 CBF 应该偏保守还是偏激进。稀疏环境自动放松，拥挤环境自动收紧。这背后有一个更本质的论点：**CBF 参数到导航性能的映射是非线性非凸的，解析方法解不了，只有 RL 能从交互经验中学会这个映射**。

更巧妙的是，它用 GNN 参数化这个策略。GNN 天然具有平移不变性和排列等变性——障碍物出现在你左边还是右边，有 3 个还是 10 个，GNN 输出一致。MLP 做不到这一点——MLP 把输入展平成固定长度向量，换一个障碍物数量或方向，输出就完全不同了。

对于 SEA-Nav 来说，这篇的三个启发非常直接。第一，论证了安全层参数应该进一步做 observation-conditioned 或 motion-conditioned 自适应，而不是只依赖通用历史编码——这也是我后续计划里的 AlphaAdapter 或 safety-margin adapter。第二，GNN 的排列等变性为从固定数量 dynamic token 扩展到可变数量障碍物提供了理论依据。第三，"为什么用 RL 调参而非解析方法"的论证为我们的长期路线提供了理论支撑。

### 第三篇：HEIGHT（2024）

这篇来自 UIUC，2024 年 11 月放出来的。它的核心创新是**首次提出了异质交互建模的概念**——这是整个调研里对我启发最大的一个思想。

传统方法包括 SEA-Nav，把所有障碍物同质化处理——射线近的就是危险的，远的就安全。但 HEIGHT 指出，不同类型的障碍物需要不同类型的处理策略。它区分了三种交互关系：Robot↔Human，机器人需要预测人的意图并主动让行——比如人正在往前走，你要预判他的未来位置绕过去。Human↔Human，人群内部的交互会影响群体的整体运动——两个人互相避让会改变各自的路径，你不能假设每个行人独立运动。Obstacle↔Agent，静态障碍物只需要保持距离就行，不需要任何预测。

它把这三种边构建成一个异质时空图，然后用多注意力头 Transformer 同时建模空间和时间维度。不同的注意力头分别关注"最近的障碍物"、"最快靠近的障碍物"、"人群密度最高的方向"，互不干扰。再加上 GRU 做时序建模来捕获运动变化趋势。

它的结果很漂亮——88% 成功率对比 64% 的 A*+CNN 基线。更让人印象深刻的是零样本 sim-to-real 泛化——在训练时没见过的高拥挤密度下，直接在真实环境里也能工作。

对我们 SEA-Nav 的启发。"异质交互"这个思想直接影响了我的观测设计——我没有把所有信息混在一起，而是把静态射线和动态 token 分成两个通道：ray 负责静态空间约束，token 负责动态运动信息。它们编码的信息类型不同，不应该被同质化处理。另外，我把 token 设计为结构化语义向量 [rel_x, rel_y, rel_vx, rel_vy, radius, ttc, valid]，而不是一个抽象 embedding——这样做保留了可解释性，也方便后续接入异质图编码器。当然当前还没有引入 GNN 或 Transformer，但 token 接口已经为这一步预留好了。

### 第四篇：Subgoal-Driven Navigation with Attention（2023）

这篇来自波恩大学。它的核心是两个设计：层次化解耦和 Self-Attention。

层次化解耦是把导航任务拆成两个 agent——Subgoal Agent 只负责"下一步往哪走"，输出二维子目标坐标；Motion Agent 只负责"怎么走过去"，处理底层运动控制。两个 agent 独立训练然后组合。这种解耦让每个 agent 的学习目标更纯粹，训练效率更高。

但在 12 篇论文中，这篇对我影响最大的是它的 **Self-Attention 机制**。它在 LiDAR 扫描的时间序列上做 self-attention——把 1080 个 LiDAR 点在过去几帧的变化一起看。策略不需要被显式告知"第 30 条激光点对应一个正在靠近的行人"，attention 权重会自动在那些"距离在快速变小的方向"上聚集。

这带来了一个很重要的推论：**不需要显式的检测、跟踪或轨迹预测模块**。Attention 从 LiDAR 点的时序变化中自动推断哪里有东西在靠近、以多快的速度靠近。这是个隐式的运动推断——不需要先检测障碍物、再跟踪它的轨迹、再预测未来位置，把整个感知管线省掉了。

他们在真实 Turtlebot 上只用 2D LiDAR 就完成了验证。

对我们 SEA-Nav 的启发。第一，SEA-Nav 有 41 条射线乘 10 帧历史，如果在这 410 个元素上加一个轻量级 self-attention，策略应该能自动学会关注"距离在快速减小的射线方向"——这是短期改进里的射线 Attention 机制。第二，层次化解耦说明端到端不一定是最优的——如果场景更复杂，可引入子目标层来降低学习难度。第三，"不需要显式轨迹预测"对工程实践的价值很高——省去了复杂的检测-跟踪 pipeline。

### 第五篇：HJ Reachability in RL — A Survey（IEEE OJ-CSYS 2024）

这篇是 UC San Diego 发表在 IEEE 控制期刊上的综述，2024 年。它的价值在于**从理论上建立了 CBF 与 HJ 可达性的关系**。

核心论点：CBF 本质上是 HJ 可达性的一种简化、保守的近似。HJ 可达性可以严格划分"安全区域"和"不安全区域"——在安全区域内，存在一个控制策略保证永远不进入不安全区域。CBF 通过构造屏障函数保证前向不变性，它是 HJ 的充分条件但不是必要条件。用大白话说，HJ 可达性证明安全的区域比 CBF 能保证的更大——CBF 是保守的。

传统 HJ 可达性有个致命瓶颈就是维度灾难——只能在大概 6 维的状态空间里求解，遇到神经网络策略的几百维状态空间就完全不行了。但这篇综述介绍了一个突破：通过学习 HJ 值函数，可以扩展到 112 维。它把学习方法分成两类：在线学习——安全值函数和策略同时训练，代表工作是 RESPO 发表在 NeurIPS 2023；离线学习——先学安全证书再约束策略。

HJ 可达性对动态障碍物有个天然优势——它支持 reach-avoid 任务，也就是"到达目标的同时避开障碍物"。而且它可以处理**非合作动态障碍物**——不假设障碍物会配合你避让，而是假设它们可能做最坏的运动，然后在这个假设下保证安全。这和我们的轨迹驱动障碍物设定一致——我们也不能假设障碍物会主动让路。

对我们 SEA-Nav 的启发。从理论上确认了 LSE-CBF 的局限——它只看当前时刻。学习 HJ 值函数可以作为安全层的长期升级方向。不过工程量大，需要新的值函数训练目标和贝尔曼方程，列在长期计划中。现阶段先做好 velocity-aware CBF。

### 第六篇：DRL Navigation in Crowded Environments（JIRS 2024）

这篇是 JIRS 上的综述，覆盖了 DQN、PPO、SAC 等主流 DRL 算法在拥挤环境中的应用。它的主要贡献是提出了五维分类框架——传感器融合、社交感知、层次化、安全约束、注意力机制——把散落在各论文里的方法组织成了体系。

但对我最重要的价值是**它明确列出了领域五个开放问题**。五个里面有两条直接对应了我本周核心工作。

第一个开放问题是"奖励函数设计：如何平衡安全、效率、平滑性"。这在动态环境里尤其困难——你只奖励到达目标，策略可能冒险穿过密集动态障碍物；你只惩罚碰撞，策略可能学会停在原地不动。怎么在安全、效率和动作平滑性之间取得平衡，是一个开放问题。我本周的近目标五项奖励加 pass-behind 奖励，就是尝试分阶段、分行为去塑形，而不是用一个全局权重去平衡一切。

第二个开放问题是"安全性保证：学习策略缺乏形式化安全保证"。SEA-Nav 的 CBF 提供了一定保障，但对动态障碍物没有形式化保证。HJ 可达性综述说的就是这个问题。

另外这篇综述还强调了一个点——"简单往复运动不等于真实动态场景"。这进一步论证了我构建复杂动态环境、多种运动模式的必要性。

### 第七篇：DRL-VO（2023）

这篇是 12 篇中应用参考价值最直接的一篇。它把传统算法中的 Velocity Obstacle 概念融入到 RL 里——在观测中加入短历史 LiDAR 和附近行人的运动学信息，在奖励中显式加入 VO 项作为风险度量。

它有两个非常扎实的实验结论。第一，在最多 55 个行人的拥挤场景中完成了训练和验证——55 个动态 agent，不是 2 到 4 个。第二，实现了**真实机器人零重训迁移**——在仿真中训练好的模型，直接部署到真实机器人上运行，不需要额外的 fine-tuning。这说明 VO/TTC 特征在 sim 和 real 之间具有足够的物理不变性。

这篇文章论证了一个核心命题：**结构先验融入 RL 比纯黑箱 RL 更有效**。传统 VO 算法已经把"相对速度会导致未来碰撞"这个几何事实提炼成了公式，你把这个结构先验作为奖励信号放进 RL，比让 RL 从零开始从大量试错中学出"靠近的障碍物危险"这个常识，要高效得多。

对我本周工作的启发。第一，将静态碰撞惩罚升级为 TTC 风险奖励——TTC 越小惩罚越大，在撞上之前就提供梯度信号。第二，动态障碍物的相对速度应该作为观测 token 的一部分，而不是让策略从射线变化中隐式推断。第三，零重训迁移的成功为我们后续的实机部署提供了信心——说明这个方向在工程上是可行的。

### 第八篇：Intention-Aware CrowdNav（ICRA 2023）

这篇来自 ICRA 2023，是做"社会导航"方向的一篇重要工作。它用 recurrent graph neural network 加 attention 来建模机器人和人群之间的时空交互，并预测动态 agent 的未来轨迹。

核心思想是：**不仅要看人在哪里，还要预测人将要走到哪里**。传统的反应式避障是被动反应——看到障碍物近了就躲。但这篇的方法让策略具有了"预期性"——提前预测人的未来路径，然后在规划时避开那些未来位置，而不是等到距离真的变近了才反应。

它把轨迹预测和导航决策统一在一个框架里——传统做法是先做检测跟踪、再做轨迹预测、最后做路径规划，是分阶段串联的。但这篇让预测模块为决策模块提供特征，端到端联合优化。注意力图网络天然适合建模双重交互——Robot↔Human 和 Human↔Human，用同一个图结构表达两种不同的关系。

对我们 SEA-Nav 的启发。它为引入 K 个动态障碍物的图注意力编码器提供了直接实现参考。如果后续我们要从固定 4 个 token 扩展到可变数量障碍物，GNN encoder 是最自然的选择。而且轨迹预测的融入可以让策略从"反应式避障"升级为"预期式避障"。适合后续社会导航方向扩展。

### 第九篇：NavRL（2024）

这篇是做 UAV 的，发表在 2024 年。它的核心结构是 PPO 学习导航决策，再加上一个受 Velocity Obstacles 启发的 safety shield——RL 负责导航效率，安全层负责最后兜底。

对 SEA-Nav 来说，这篇的价值不在于具体方法，而在于**它为我们的架构路线提供了独立的工程验证**。SEA-Nav 也是"PPO + CBF safety layer"的双层架构。如果这个架构仅在静态环境中有效，那到了动态环境就需要推翻重来。但 NavRL 在 UAV 的动态避障中独立验证了同样的范式——说明"RL 负责决策、安全层负责兜底"这个思想在动态环境中也是成立的，不是只适用于静态。

它用 VO 的几何原理设计 safety shield，而不是黑箱网络，保证了安全层的可解释性和可靠性——你知道安全层会在什么条件下介入、怎么介入、为什么。这和我们的 velocity-aware CBF 设计思路是一致的。

对我们 SEA-Nav 的启发。为 PPO + CBF 路线在动态环境中的有效性提供了独立工程验证。后续可考虑增强 CBF 安全层，使其融合更多的 VO 思想——不仅是距离约束，还有速度约束。这也是 velocity-aware DynamicTokenCBFLayer 的设计意图。

---

### 第十篇：One Filter（2024）

这篇提出了一个很重要的概念——**observation-conditioned reachability-based safety filter**。它和传统 CBF 的关键区别在于"observation-conditioned"。

传统 CBF——包括 SEA-Nav 当前的 LSE-CBF——是 state-conditioned 的。它基于已知的状态信息（如障碍物位置距离）计算约束。但这种做法假设你知道完整的状态。One Filter 提出：安全区域应该根据当前的**原始传感器观测**实时构造——不要求完整状态，不要求地图，直接从 LiDAR 输入动态计算安全区域，在必要时覆盖 nominal controller。

这点对四足机器人尤其重要——你在未知环境中走，不能假设每个障碍物的位置速度都已知。它从原始传感器出发来保证安全，更贴近真实部署条件。

而且 One Filter 被验证可以适用于不同四足控制器——它是个"即插即用"的模块，不依赖特定的控制策略。

对我们 SEA-Nav 的启发。它是 SEA-Nav 安全层下一阶段升级的最明确方向——把当前 LSE-CBF 升级为以观测（射线 + token）为条件的动态安全过滤器。安全裕度不再是全局固定配置，而是根据当前局部环境实时计算——拥挤时紧、稀疏时松、障碍物靠近时紧、远离时松。

---

### 第十一篇：REASAN（2025）

这篇是 2025 年最新放出来的工作，做的是面向复杂动态环境的四足反应式安全导航系统。它最大的特点是**系统级的模块化设计**。

它把整个导航系统分成四个模块：locomotion 负责底层运动、safety shielding 负责安全兜底、navigation 负责高层导航决策，再加上一个 Transformer-based exteroceptive estimator 负责处理 LiDAR 点云。四个模块各自独立训练，组合使用时互不干扰。

这种模块化设计的优势在哪？对比端到端的单一策略——一个网络从像素到控制指令全部包办——如果出了问题你很难判断是感知出错了还是决策出错了。模块化的话，你可以分别检查每个模块的工作状态，定位问题的速度要快得多。

对我们 SEA-Nav 的启发。它提供了一个系统级参考架构。SEA-Nav 当前已经有两个模块了——navigation（导航策略）和 safety shielding（CBF 安全层）。缺的是显式的感知估计器——我们现在直接把观测向量喂给策略，没有中间的感知理解层。后续可以参考 REASAN 的模块化设计，将感知、安全、导航三层解耦——感知层负责理解环境、安全层负责保证安全、导航层负责到达目标。

---

### 第十二篇：Omni-Perception（2025）

最后一篇，也是 2025 年的工作。它做的是时序 3D LiDAR 点云端到端四足全向避障。核心创新是提出了 **PD-RiskNet**——把碰撞风险分成近端风险 Proximal Risk 和远端风险 Distal Risk，然后用不同的网络分支分别处理。

为什么近端和远端需要分开处理？近端风险需要快速反应型策略——障碍物已经到眼前了，你需要马上减速或侧移。远端风险需要规划型策略——障碍物在几米外但正在靠近，你需要提前调整路径。这两种风险的时间尺度不同、需要的响应类型不同，用同一个网络处理会造成信号竞争。PD-RiskNet 通过分离两条通路解决了这个问题。

它还从传统的 2D LiDAR 水平扫描扩展到了 3D 全向感知——不再只扫一个水平面，而是能看到上方和下方的障碍物。

对我们 SEA-Nav 的启发。后续可从 2D sparse LiDAR 扩展到 3D LiDAR 全向动态避障。近端/远端风险分离的思想可以直接融入当前的奖励设计——近端风险用重惩罚压制，远端风险用轻引导塑形。而且它支持 Isaac Gym，和我们的仿真栈兼容。

### 从十二篇文献中归纳出四大方法类别

好，十二篇论文讲完了。现在我来做一个归纳。

我把这 12 篇论文归入了四大方法类别。大家请看投屏上的表格。

第一类是 VO/TTC 引导的强化学习，归属论文包括 DRL-VO 和 NavRL。核心思想是把速度障碍和碰撞时间的结构化先验融入观测和奖励。**这个类别本周已经落地了**——观测中加入了 dynamic token（包含 TTC 和相对速度），奖励中加入了 TTC 风险项和 pass-behind 方向奖励。

第二类是 CBF、安全过滤器和可达性理论，归属论文包括 Online CBF、One Filter、REASAN、NavRL 和 HJ Reachability Survey。核心思想是策略负责导航效率，安全层负责约束保障，参数可以自适应或者以观测为条件动态调整。**这个类别本周也部分落地了**——velocity-aware DynamicTokenCBFLayer 已经实现。长期来看，可以升级为 observation-conditioned safety filter。

第三类是 Reach-Avoid 值网络和恢复策略，归属论文包括 Agile But Safe、One Filter 和 HJ Reachability Survey。核心思想是学习预测未来碰撞风险的值函数，高风险时自动切换行为模式。**这一类本周没有直接采用，但预留了扩展接口**——RA 值网络将来可以调节 CBF 的动态安全裕度，near-miss replay 可以为恢复策略提供训练数据。

第四类是图网络、Transformer 和注意力机制的交互建模，归属论文包括 HEIGHT、Intention-Aware CrowdNav、Subgoal-Attention 和 Omni-Perception。核心思想是显式建模机器人和障碍物之间的时空交互关系，区分不同类型的关系。**这一类本周保留了接口**——dynamic token 的结构化语义向量将来可以直接接入 GNN 或 Attention encoder，射线 Attention 列在短期改进计划中。

### 交叉验证：十二条文献的共同指向

最后我要强调一个很重要的观察。请大家看投屏上的交叉验证矩阵——十二篇论文，四个技术维度，哪些文献强调哪些维度一目了然。

## 第三章：方法选择与路线设计（2-3 分钟）

接下来看方法选择。

面对四类方法，不能全上，必须做取舍。取舍的标准是三条：改动代价、可诊断性、可扩展性。

VO/TTC 引导的方法我直接采用了，因为它可以直接增强观测和奖励，改动最小，而且可解释性强——你加了一个 TTC 指标，策略就知道某个障碍物正在快速靠近，这非常直观。CBF 安全层升级我也采用了，因为 SEA-Nav 本来就有 LSE-CBF，把它从静态扩展为 velocity-aware 是很自然的演进。

但 Reach-Avoid 值网络和恢复策略，本周我没有直接上。原因不是因为它们不好——恰恰相反，Agile But Safe 和 One Filter 的研究价值非常高。但 Reach-Avoid 值网络需要新的安全值函数训练目标，工程量明显更大。更重要的是，当前复杂环境本身还没有一个稳定的训练基座，如果这时候再加一个值网络，出了问题你很难判断是环境有问题还是新网络有问题。应该是先把基座跑通，再往上加东西。

同理，图网络和 Transformer 我也暂时没有引入。因为当前的动态障碍物是轨迹驱动的物理体，它们之间并没有真实的交互意图——障碍物 A 不会因为障碍物 B 靠近就主动避让。在这种设定下引入交互建模是过度设计。但我保留了 top-K dynamic token 接口，每个 token 有独立的位置、速度和 TTC 信息，后续可以很自然地接 GNN 或 attention encoder。

所以确定的路线是 Motion-Aware SEA-Nav。核心思路是：在原 PPO 加 LSE-CBF 基座上，加入三样新东西——dynamic token 提供运动感知、velocity-aware CBF 提供动态安全保障、还有 near-miss replay 框架。然后在这个可靠基座之上，再逐步考虑 GNN、Transformer 或 Reach-Avoid 等更大改造。

这条路线遵循三个原则。最小改动原则——每次只做定向扩展，不大改骨架。可诊断原则——每次只引入一项新机制，通过指标判断方向，而不是打包修改，出了问题不知道哪个改动起作用。可扩展原则——现在的 dynamic token 将来可以接 GNN，velocity-aware CBF 将来可以升级为 observation-conditioned safety filter。

## 第四章：复杂动态障碍物环境搭建（3-4 分钟）

翻到系统实现的第一部分——环境搭建。

上一周我复现了 go2_pos_dynamic_1/2/3 三个简单动态环境，验证了系统可以在有动态障碍物的情况下训练。这一周的任务是把场景复杂度提升到 complex 级别。

首先是观测空间的设计。我把它从原来的 550 维扩展到了 830 维。在本体状态、41 条射线和目标方向之外，新增了 4 个 dynamic token，每个 token 包含七个元素：相对位置 x y、相对速度 vx vy、障碍物半径、碰撞时间 TTC、还有一个 valid 标志位表示这个 token 是否对应真实障碍物。83 维单帧叠 10 帧历史就是 830 维。这样设计的好处是策略能同时看到射线的空间分布和动态障碍物的运动信息——射线告诉它哪个方向有东西，token 告诉它那个东西的运动状态。

第二是静态障碍物的重新布局。这里有一个容易被忽略但很重要的细节。最初的复杂环境把 19 个静态障碍物集中在房间中央，结果四周形成了一圈比较空旷的区域。我通过录像发现，机器人可能就绕到这个外圈通道走，从而回避了真正复杂的避障问题——你看着它在训练，但其实它在作弊，走的外圈通道。所以我重新调整了障碍物的分布，让 19 个 boxes 在整个 10 米乘 10 米的房间内更均匀地分布，消除了"外圈作弊通道"。这一步确保了机器人在训练中必须面对避障问题，而不是找空子钻。

第三是动态障碍物的轨迹生成方式，这是我本周花了很多精力解决的一个工程问题。

早期的实现是在线采样加在线推进——每个 step 都去算障碍物该往哪走，碰到边界就反弹，跟别的障碍物撞了就重采样。在高密度场景下，这个方式有两个严重问题：一个是性能瓶颈，Python 循环和 PhysX 接触求解拖慢了整个训练；另一个是运动不稳定，障碍物会抖动、有时候几乎在原地不动。

导师也要求我改进这一点。所以我把它改成了 episode 预生成轨迹的方式——在 episode 初始化的时候，一次性生成每个动态障碍物在整个 episode 内的完整轨迹，step 阶段只需要按当前步数去读轨迹缓存里的位置和速度。同时用 `disable_simulation_contacts = True` 跳过 PhysX 对动态障碍物的接触求解，只保留机器人与障碍物的几何碰撞检测。轨迹缓存是 `[num_envs, max_obstacles, trajectory_len, 2]` 的张量，全部用张量索引操作，没有 Python 循环。

当前支持四种运动模式：横向穿行 linear_crossing、斜向穿行 linear_diagonal、圆形 circular 和八字形 figure_eight。这些模式覆盖了大部分有代表性的动态交互场景。

这一步做完之后，32 个环境 200 步的训练可以流畅运行，step 阶段不再卡在障碍物初始化或推进的逻辑上。

## 第五章：网络与安全层修改（5-6 分钟）

翻到网络修改这一页。这一章我想从设计决策讲起，深入到数学原理，再到诊断体系的设计逻辑。

---

### 设计决策：为什么不推翻原架构？

面对 SEA-Nav 现有的 PPO 加 LSE-CBF 框架，设计上有两条路。一条是推翻重建，用全新的 Reach-Avoid 值网络或 GNN 编码器替代现有架构。另一条是保留主干，做定向扩展。我选择了后者。

这个选择有三个层面的考虑。

第一是风险维度。如果新架构和新环境同时调试，出了问题你很难判断是环境有问题还是新网络有问题。引用空间太大，不方便排查。保留原主干，每次只引入一项新机制，可以逐个验证——先确认环境跑通了，再确认动态 CBF 起作用了，再确认奖励方向对了。

第二是继承性维度。SEA-Nav 的静态 CBF 安全层已经经过验证，在静态密集障碍物中提供了可靠的安全保证。如果推翻它，就需要从头验证新安全机制在静态场景中是否等价有效。保留它，静态 CBF 继续处理静态障碍物，动态 CBF 作为一个补充层只处理动态障碍物，各司其职。

第三是可解释性维度。串行管线每一步的输出都可以独立观察——u_bar 是什么、u_static_safe 是什么、u_s 是什么、每一步修正了多少角度。如果是端到端的新架构，这些中间信号就不存在了。

### 动作处理管线：串行投影的深层原因

我设计的动作处理管线是四步串行。PPO 策略先输出 u_bar，经过静态 LSE-CBF 得到 u_static_safe，再经过新增的 DynamicTokenCBFLayer 得到最终的 u_s。

这里有一个关键的设计选择：为什么是串行——先静态后动态——而不是并行投影？

这个选择的根本原因是两种安全约束处理的信息类型不同。静态 CBF 处理的是"空间是否被占据"，这是位置层面的硬约束——"那个位置有墙，你不能往那边走"。动态 CBF 处理的是"运动是否危险"，这是速度层面的软约束——"虽然那个方向现在空着，但有东西正在往那边走"。

如果你把两个约束并行，可能出现一个悖论：静态 CBF 说往左走安全（左边没墙），动态 CBF 说往左走不安全（有障碍物正在往左走），两个投影方向互相矛盾，二次规划求解就会不稳定。

串行设计避免了这个问题：先让动作在"不被墙挡"的可行空间里投影，再在这个子空间里投影到"不被动态障碍物撞"的方向。这保证了每一步投影都有明确的物理含义，不会出现两个安全层打架的情况。

另外，yaw 动作在整个管线中保持透传——只有 [vx, vy] 被修正。这是一个有意的简化。yaw 不直接影响碰撞——碰撞取决于位置变化，位置变化主要由 [vx, vy] 决定。yaw 只影响朝向，而朝向本身不造成碰撞。保持 yaw 透传的好处是策略仍然可以自由调整朝向，不会被安全层锁死在一个方向。

### DynamicTokenCBFLayer 为什么没有可训练参数？

这是一个容易被质疑的设计选择——毕竟 Online CBF 那篇论文就是用一个 GNN 来学习 CBF 参数的。为什么我选择了一个没有学习参数的解析版本？

我是这样考虑的。CBF 的安全屏障函数有一个非常强的物理先验——距离越近越危险、靠近比远离危险。用 h 等于距离平方减去安全距离平方，这个形式已经编码了"安全距离"的物理直觉。dot(h) 等于两倍的相对位置点乘相对速度，这个导数天然区分了靠近和远离。

如果用一个神经网络来替代这个解析形式，它确实更灵活——可以学到"某些情况下虽然靠得近但可以激进，某些情况下虽然离得远但要保守"。但这个灵活性在当前阶段是负担而非优势——你需要额外的训练数据和训练目标来约束这个网络，如果网络没训好，它可能输出不安全的约束。而解析形式从第一行代码开始就是保证安全的。

所以当前的选择是"先用无参数版本跑通基座，后续可以按 Online CBF 的思路替换为可学习的参数调度器"。我保留了这个升级接口——DynamicTokenCBFLayer 可以无缝替换为一个带参数的版本，只需要把固定的 safety_margin 变成网络的输出。

### Velocity-Aware CBF 的数学：从直觉到公式

现在我想深入讲一下这个 CBF 约束的数学推导，因为这体现了"从物理直觉到数学形式"的思维过程。

第一步，静态 CBF 的屏障函数是 h 等于射线距离减去安全距离。这是一阶形式。一阶形式在静态环境里没问题，因为"距离"就是唯一的危险指标。

但动态障碍物有一个额外信息——相对速度。我们需要一个能编码相对速度的数学形式。第一步升级是改用距离平方：h 等于相对位置的范数平方减去安全距离平方。这是二阶形式。

为什么用二阶？不是任意的。一阶形式在求导时，dot(h) 正比于 1 除以距离——距离趋近于零时导数趋近于无穷，这在数值上是不稳定的。二阶形式的导数正比于相对位置点乘相对速度，在任何距离上都是一个平滑的线性函数，数值稳定。

而且范数平方天然是凸函数，这保证了 CBF 的二次规划求解有唯一的全局最优解——不会有多个可行解让你纠结选哪个。

第二步，CBF 的核心约束是 dot(h) 加上 alpha 乘 h 大于等于零。展开来就是：2 倍相对位置点乘 (障碍物速度减去机器人速度)，加上 alpha 乘 (距离平方减去安全距离平方)，大于等于零。

注意这里障碍物速度减的是机器人的动作 u——不是机器人的当前速度，而是策略输出的目标速度。这意味着 CBF 不是在评价"当前状态是否危险"，而是在评价"如果执行了这个动作会不会危险"。它是一个动作过滤器，不是状态评估器。

第三步，点积符号的物理意义。如果障碍物正在远离你，相对位置和相对速度同向，点积是正的，dot(h) 天然是正的——约束自动满足，不需要任何修正。但如果障碍物正在靠近，点积是负的，dot(h) 是负的——你需要额外的安全裕度（alpha 乘 h 项）来保证约束成立。距离越近 h 越小，安全裕度越小，需要的修正就越大。

这就是 velocity-aware——安全约束的强度不是固定的，而是由相对运动状态自动调节的。

### 从设计阶段就预见到的问题

在设计 DynamicTokenCBFLayer 的时候，我其实已经预见到它在三个方面的天然局限。

第一个局限是它只约束线速度，不约束 yaw_rate。如果障碍物很近，策略可能原地转向朝向障碍物。物理上这不算碰撞——你没有平移，就不会撞。但行为上这不优雅——你对着一个障碍物盯着看。

第二个局限是它没有前瞻性。CBF 只看当前这一帧的相对位置和速度，不知道 0.5 秒后障碍物会在哪里。如果有一个障碍物正在以一个弧线轨迹弯过来，CBF 在当前帧可能判断"距离够远"，但 0.5 秒后它就到了。这是 HJ 可达性综述明确指出的 CBF 理论局限。

第三个局限是当多个障碍物同时靠近时，多个 CBF 约束叠加。每个障碍物给你一个"不能往那边走"的半平面约束，多个约束的交集可能把安全动作压缩到一个极小的空间——甚至接近零向量。这就是 freezing robot problem 在动态场景中的体现。

但这些局限不是 bug，而是我有意接受的简化。每个局限都有对应的后续升级方案——yaw 可以加入约束、Reach-Avoid 值网络可以提供前瞻、介入率衰减 curriculum 可以逐步放开约束让策略自己学。现阶段先让基座跑通，再逐个解决这些局限。

### 诊断指标的体系化设计

最后我想讲一下我新增的那些诊断指标。它们看起来是一堆指标罗列，但实际上有一个分层的设计逻辑。

我把它分成四层。最顶层是安全结果层——撞了没有、撞了多少次、最小距离是多少。这是最终的目标指标。

第二层是安全机制层——静态 CBF 在多少时间步介入了？动态 CBF 在多少时间步介入了？Pass-behind 评分是正还是负？这层告诉你：如果安全结果不好，是哪个安全机制出了问题。

第三层是动作归因层——u_bar 和目标的偏差角度是多少？u_static_safe 又修正了多少？u_s 最终偏离了多少？这层能区分"nominal policy 方向就偏了"和"policy 方向对但 CBF 修正过度"两种完全不同的失败原因。

第四层是环境归因层——reset 是被 contact force 触发的还是被动态碰撞触发的？当前面对几个活跃的动态障碍物？这层帮你判断失败是因为环境设置不合理还是策略本身的问题。

这个分层设计的价值在于它支持逐层归因。比如碰撞率高，你先看第二层——是 CBF 没介入还是介入方向不对？如果是介入方向不对，pass_behind_score 是负的，那说明是奖励设计的问题。如果 CBF 介入率很高但碰撞率还是高，那说明 CBF 的安全裕度设置有问题。如果 CBF 介入率很低但碰撞率很高，那说明 nominal policy 本身的方向就很差，需要调整主策略的训练。每一层都指向不同的修复方向，避免了出了问题就盲目调参。

这个诊断体系在后面的排错中发挥了关键作用——等一下讲 success=0 的案例时大家就会看到。

## 第六章：奖励函数设计（5-6 分钟）

翻到奖励函数这一页。这是本周我投入思考最多的一章，因为动态避障的奖励设计和静态避障有本质的不同，需要从第一性原理重新思考。

### 静态避障 vs 动态避障：奖励逻辑的根本差异

静态避障的奖励逻辑非常直接——离障碍物近就危险，给予碰撞惩罚，策略学会保持距离。这个逻辑之所以成立，是因为在静态环境里，"距离"是危险的充分统计量。

但动态环境打破了这个充分性。同样是一米的距离，如果障碍物正在以每秒零点三米的速度远离你，这个距离正在变大——你不需要任何规避动作。但如果障碍物正在以同样的速度靠近你，三秒后你们就会相撞——你需要立刻规避。距离完全一样，但危险程度完全不同。

更关键的是，PPO 的信用分配机制是时序差分的。它从最终的碰撞信号出发，通过 TD-error 往回传播梯度。但这个梯度在时间维度上非常稀疏——从"三秒前应该选择从障碍物后方绕而不是前方"这个具体的行为决策，到三秒后的碰撞，中间隔了上百个时间步。梯度在这个过程中不断衰减，最终到达关键决策点的信号已经非常弱了。

这就是为什么只加碰撞惩罚不够的根本原因。不是 PPO 不够好，而是信用分配问题——你需要更密集、更即时的梯度信号来引导具体的行为决策。必须通过奖励塑形把结构化的运动先验注入训练信号，告诉策略在每一个中间状态上它的行为是好是坏。

### 从视频到奖励：完整的诊断-假设-设计-验证闭环

我不是凭空设计了这些奖励项，而是走过了一个完整的诊断-假设-设计-验证循环。

起点是 Run 2 model_500 的视频。我花了大量时间逐帧检查 10 个 episode 的录像，发现了两个反复出现的失败模式。

失败模式 A：目标点已经很近了，不到两米，但机器人不往目标走，而是绕着它画大圈——有时候甚至绕了几乎一整圈才到达，有时候干脆绕远了就回不来。这说明什么？说明在近目标区域，goal_progress 这个奖励的梯度信号太弱了——因为距离变化已经很小，progress 值本身就接近于零，产生的梯度非常微弱。策略在近目标区缺乏有效的行为引导。

失败模式 B：障碍物从右往左运动，机器人看到"左边有障碍物"，于是也往左躲。但障碍物正在往左走——0.5 秒后，机器人到了更左边，障碍物也到了更左边，他们在新的位置相遇了。策略完全没有"障碍物也在移动"的概念——它的避障逻辑是纯静态的："那个方向有东西，我换个方向"。它不知道换了方向之后，那个东西也跟着来了。

基于这两个观察，我提出了两个假设。针对模式 A：如果给予更密集、更结构化的近目标行为引导，策略应该能学会在靠近目标后稳定收敛。针对模式 B：如果奖励中包含运动方向的信息——具体来说，奖励机器人从障碍物运动方向后方通过的行为——策略应该能学会更安全的让行方式。

然后我设计了对应的奖励项，在 Run 3 中测试。Run 3 model_400 的结果——pass_behind_score 变成正值，success 提升到 89.6%，视频中 pass-behind 行为明显改善——初步验证了假设。

### 三阶段奖励分解的学理基础

我把奖励空间分解为三个正交阶段的根本原因，是动态避障有一个本质性的多目标冲突——安全要求你远离障碍物，效率要求你靠近目标。这两个目标在很多情况下是冲突的。

如果你用一个全局的权重去平衡这两个目标，结果往往是最差的折中——保守的权重导致 freezing robot problem，激进的权重导致碰撞。而且这个平衡点是环境相关的——稀疏环境需要更多的效率权重，拥挤环境需要更多的安全权重。

分阶段的核心思想是：在不同的状态区域激活不同的奖励子集，让每个区域的优化目标更纯粹。远离目标的时候，重点只有一个——往前推进。靠近目标的时候，重点变成——收敛和停下。动态交互的时候，重点变成——从哪个方向让行。三个阶段的奖励不会同时全部激活，减少了梯度信号之间的相互干扰。

这里有三个设计上的细节值得讲。

第一，阶段之间不是硬切换的——它们可以同时激活。比如你在近目标区域同时遇到了一个动态障碍物，那么近目标奖励和动态让行奖励都会给你梯度信号。它们本身是正交的——一个关心你离目标多近，一个关心你相对障碍物在哪个方向——不会互相矛盾。

第二，激活条件是平滑过渡而非硬阈值的。TTC 小于 1.2 秒时激活动态让行奖励，但奖励的强度是连续的——TTC 越小，权重越大。同样，近目标区域的奖励强度随距离的减小而增加。这种连续设计避免了"在阈值附近突然变化导致梯度不连续"的问题。

第三，负奖励（惩罚）的绝对值设置得比正奖励更大。near_goal_orbit_penalty 是负 4，而 near_goal_radial_reward 是正 4——看起来对称。但 negative_progress_penalty 是负 5——比大部分正奖励都重。这里的逻辑是：在强化学习中，稀疏采样的负信号需要更大的绝对值才能产生足够的梯度，因为负事件（如"正在远离目标"）的发生频率远低于正事件（如"正在靠近目标"）。

### 近目标五项奖励的深入解析

这五项奖励不是我随便列了一堆数值，每一项都源于对具体失败行为的物理分析。


**第一项，near_goal_radial_reward。** 我把机器人的速度向量投影到"指向目标"的方向上。如果这个径向分量是正的——机器人在朝目标走——就给奖励。如果是负的或者趋近于零——机器人没有在靠近目标——就不给。

这里有一个细节：我只奖励正的径向分量，不惩罚负的。原因是近目标时策略可能需要小幅度后退来调整姿态——比如 CBF 把它推远了一点。如果惩罚所有后退，策略可能卡在原地不敢动。所以这个奖励是"正向引导"型的，而非"负向惩罚"型。

**第二项，negative_progress_penalty。** 这是针对最让我困扰的一个失败模式——机器人已经到了离目标很近的位置，然后一个绕行动作又把它带远了。我直接比较当前距离和上一帧距离：如果距离变大了，说明正在远离目标，直接给一个 -5 的惩罚。

为什么权重设为 -5，比 goal_progress 的 +6 还重？因为"绕远再回来"的时间代价远大于"慢一点走直线"。"从目标旁边绕远"是一个不应该被容忍的行为，所以惩罚需要足够大到让策略宁愿慢一点也不愿意绕远。

**第三项，near_goal_orbit_penalty。** 这个设计直接来自视频中观察到的"画圈"行为。我计算了两个量——径向速度和切向速度。如果切向速度远大于径向速度，说明机器人的主要运动方向不是朝向目标而是环绕目标——这就是"绕圈"。用两者的比值而不用绝对阈值来判断，是因为不同速度下的"绕圈"表现不同，比值能自动适应速度尺度。

**第四项，near_goal_command_penalty。** 前三项都是从位置和速度的结果层面给反馈。这一项从动作命令的根源层面给反馈。如果 nominal policy 在近目标时输出了一个很快的或者横向的导航命令，直接给惩罚。这样做的好处是引导 policy 自己学会在近目标时输出更保守的动作，减少对 CBF 修正的依赖。

但这个惩罚的权重只有 -2，相对最轻。原因是如果动作惩罚过重，策略可能学会"只要你训我，我就不动"——降低速度到零确实不会被罚，但也到不了目标。所以动作层面的惩罚需要轻到只纠正明显的错误，不能压制正常的接近行为。

**第五项，near_goal_stop_reward。** 这是五项中唯一一个纯正向引导"终点行为"的奖励。前四项都在压制不良行为——绕圈、漂移、过快——这一项告诉策略"到了之后稳定停下是好的"。如果距离非常近、速度很低、yaw 转的也很慢，就给持续的停驻奖励。

这里有一个容易被忽视的关键设计——它是持续给的，不是只给一次。如果只在"到达目标"的那个瞬间给一次 reward，策略可能学会"碰一下目标区域就往前走"——因为一次奖励拿完了，继续停在原地没有新的奖励。持续给奖励让策略有动力维持停驻状态，而不是"碰了就走"。

### Pass-Behind 奖励：从直观观察到几何建模

这是本章最有几何美感的一段推导。

问题最早是在 model_500 的视频中发现的。障碍物从右往左运动，机器人看到"左边有障碍物"，于是决定往左躲。但障碍物也正在往左走——0.5 秒后，他们都到了更左边，撞上了。这是一个典型的"只看位置不看速度"的失败。

我需要一个数学量，能够区分"机器人在障碍物的运动方向后方"和"前方"。我的推导是这样：取障碍物运动方向的单位向量——就是它的速度向量除以速度大小。再取"障碍物相对机器人的位置向量"。如果这两个向量的点积是正的，说明从机器人指向障碍物的方向和障碍物自己的运动方向是大致相同的——这意味着障碍物正在从机器人所在的位置朝远处走，机器人在障碍物的"后方"。反过来的话，机器人在障碍物的"前方"，障碍物正在朝机器人所在的方向运动。

这个 pass_score 被除以相对距离的范数进行归一化，保证它只衡量方向不衡量距离——距离的远近由 TTC 和 CBF 来管。

激活条件有三层过滤。第一层，只在 TTC 小于 1.2 秒时激活——距离远的时候不需要任何方向引导，往哪走都安全。第二层，只在障碍物速度超过 0.05 米每秒时激活——静止的障碍物没有"运动方向"。第三层，只在机器人有侧向运动时激活——如果它只是在减速或者直走，它还没开始做"绕行的方向选择"，不需要引导它从哪边绕。

这个设计和 DRL-VO 论文中的 VO reward 对比一下。VO reward 是维护一个速度障碍锥体，惩罚任何进入锥体的动作。Pass-behind reward 比 VO reward 轻量很多——不需要维护锥体，只需要一个方向点积。但代价是它没有 VO 的严格几何保证——pass_score 为正不保证一定安全，它只是一个统计上有利的启发式信号。这是我接受的一个 trade-off：用更轻量的计算代价换取更密集的方向梯度。

### CBF 边界与碰撞阈值对齐：一个系统性矛盾的发现与修复

最后讲一个容易被忽视但非常关键的细节——CBF 边界和碰撞阈值的对齐问题。这个问题如果不是我专门去看数值，可能完全发现不了。

我在分析 Run 2 的碰撞事件时注意到一个异常：有些动态碰撞事件中，CBF 没有任何干预记录，但环境却判了碰撞。这说明存在一个数值区间——在某个距离范围内，CBF 认为安全的动作环境却判碰撞。

我追踪了数值。动态障碍物的默认半径是 0.32。最初 DynamicTokenCBFLayer 的 safety_margin 设的是 0.20。所以 CBF 在距离小于 0.52 时开始约束。但环境判定动态碰撞的阈值是 0.65。这就产生了一个矛盾区间——距离在 0.52 到 0.65 之间时，CBF 已经放行了（距离大于 0.52），但环境可能在下个仿真步就判碰撞（距离已经到了 0.65 以下）。

这个矛盾信号对 PPO 训练是致命的。CBF 告诉策略"你选的这个动作没问题，我不修正你"，策略拿到一个正向的 action 梯度。但环境在下一步告诉策略"你撞了，你这整个 episode 白干了"，策略又拿到一个巨大的负向 episode 梯度。同一段轨迹，CBF 说是好的，环境说是坏的——策略无法判断到底该学什么。

修复方案很简单但需要精确计算。我把 safety_margin 从 0.20 调到 0.35，实际安全距离变成 0.67。0.67 大于 0.65——CBF 的约束永远在环境碰撞判定之前生效。0.02 的裕度不是随意取的——考虑到 Isaac Gym 的仿真步长是 0.02 秒，最大相对速度大约 0.5 米每秒，单步最大位移大约 0.01 米。0.02 米的裕度刚好覆盖一个仿真步长内可能的位置变化不确定性。

这个修复的本质是保证了一个系统性的不变量：**CBF 安全约束永远先于环境碰撞判定触发**。从此 CBF 和环境不会再对同一段轨迹给出矛盾的判决。这是一个系统设计层面的保证，不是调参。

## 第七章：训练实验全景（5-6 分钟）

翻到训练实验全景这一页。这里我给大家三张表的对比。

在讲具体数字之前，我先强调一下本周真正做完的工程闭环。它不是只改了一个 reward，也不是只跑了一次训练，而是把复杂动态避障从"想法"推进到了一个可以反复训练、评估、录像和诊断的实验系统。

这个闭环从文献调研开始，先决定采用 VO/TTC、动态 CBF 和 pass-behind 方向奖励这些相对可控的机制。然后进入环境层：构建 go2_pos_dynamic_complex，重新布局 19 个静态障碍物，把动态障碍物从在线推进改成 episode 预生成轨迹。再进入观测层：把动态障碍物做成 4 个结构化 token，包含位置、速度、半径、TTC 和 valid 标志。再进入安全层：保留原静态 LSE-CBF，新增 DynamicTokenCBFLayer，形成先静态后动态的串行安全过滤。再进入奖励层：针对视频暴露的问题，加入近目标五项奖励和 pass-behind 奖励。最后进入诊断层：训练过程自动写 train_metrics.csv，训练后生成 success、安全事件、CBF 介入、pass-behind、动作目标对齐、reward breakdown 等图，并且录制 checkpoint 视频做人工检查。

所以本周的工作量可以概括成一条链：环境可跑、策略可训、指标可记、曲线可画、视频可看、问题可归因。后面所有结果分析都建立在这条链上。

本周一共跑了三次完整的训练 run。每次 500 iterations，但环境设置和结果非常不同。

第一次是在 6 月 20 号凌晨 5 点 14 分启动的。当时用的还是 Hard complex 的初始配置——6 到 10 个中高速动态障碍物，64 个环境，500 次迭代。结果是什么？success 等于零。不是接近零、不是很低，就是零。所有 episode 都成功不了。而且 episode length 平均只有 9 步——9 步什么概念？一个有效 episode 应该几百步，9 步意味着策略刚开始就被 reset 了，PPO 几乎没有有效经验可以学习。

第二次是修复了 contact reset 问题之后，在早上 7 点 23 分启动的。我把难度降到 Easy——2 到 4 个低速障碍物。这次已经有进展了——最终 success 到达了 0.29，最好窗口甚至到了 1.0。说明修复方向是对的，但策略还不稳定。视频中也暴露出近目标绕远和动态让行方向错误的问题。

第三次是 6 月 21 号凌晨 4 点 28 分启动的，在第二次优化了奖励函数之后。环境数从 64 扩到 128，还是 Easy 难度。这次训练最有意思的地方是——它不是最终 iteration 最好，而是在中间 iteration 出现了明显更好的窗口。iteration 400 的时候，success 到了 0.8958，safe_success 也是 0.8958，动态碰撞只有 0.02，pass_behind_score 是正的 0.16。但继续训练到 iteration 490，success 掉到了 0.54，动态碰撞反弹到 0.46，pass_behind_score 变成了负的 0.12。

这是一个非常重要的信号——训练后段出现了退化。也告诉我不能默认取最后一个 checkpoint，而是要基于评估和视频来选择最佳模型。

这里我建议组会投屏重点看三张训练曲线图。

第一张是 success 和 safe_success 曲线。它说明两个事实：策略确实学起来了，success 从早期接近零逐渐上升到 0.8 以上；但 safe_success 后段明显回落，说明后期训练不是单调变好。这张图支撑的是"奖励方向有效，但 checkpoint 选择很重要"。

第二张是 dynamic_direction 图。上半部分的 pass_behind_score 在 model_400 附近变成正值，这和表格里的 +0.1614 对应，说明 dynamic_avoid_direction_reward 的方向是有作用的。可是在最终窗口它又回到负值附近，这和 final safe_success 下降一致。这张图支撑的是"pass-behind 机制有效但不稳定，需要消融和稳定训练"。

第三张是 safety_events 图。model_400 附近 dynamic collision 很低，但后段 body collision 和 total collision 又反弹。这个图可以解释为什么最后一个 checkpoint 不如 model_400，也说明不能只看成功率，还要看碰撞类型和 near-miss。

如果老师追问安全层是否过度介入，我会再展示 CBF intervention 图。它显示 shield_intervention_step_rate 长期接近 1.0，说明静态安全层几乎每步都在修正动作。这不是单纯的坏事，它帮助策略早期避免大量碰撞；但长期看，它也提示 nominal policy 可能在把安全责任外包给 CBF。

最后一张备用图是 action_goal_alignment。u_bar、u_static_safe 和 u_s 与目标方向的夹角整体同步下降，说明 policy 和安全层输出都逐渐更接近目标方向；但三条曲线之间差距不大，也说明很多时候不是 CBF 单独把动作改坏，而是 nominal policy 本身仍需要更强的方向学习。这就是下一阶段为什么要做动作归因，而不是只调 CBF 参数。

## 第八章：排错过程深度分析（3-4 分钟）

这是本周最有故事性的一章，也是我最想跟大家分享的方法论收获。

我梳理了五个关键问题的完整发现-诊断-修复链条。

第一个问题，训练过慢。64 个环境训练时明显卡顿。我分析后发现是在线采样中存在大量的逐 env、逐 slot 的 Python 循环逻辑，尤其是障碍物的间距检查、bbox 有效性检查和线性轨迹推进。解决方案就是前面讲过的 episode 预生成轨迹。

第二个问题，动态障碍物原地抖动。我录了视频检查，发现有些障碍物几乎没有在运动，就原地抖。追踪后发现两个原因：一是障碍物仍然在被 PhysX 接触求解影响——即便你不希望它们有物理碰撞，Isaac Gym 也在算；二是在线反弹逻辑在局部区域反复触发，导致障碍物在边界附近高频反弹。我通过 disable_simulation_contacts 和预生成轨迹彻底解决了这个问题。

第三个问题是本周最关键的排错——success 等于零。

看训练曲线，success 就是零，一条平线。一开始我以为是安全层太保守了，策略不敢走——因为 shield_intervention_rate 接近 100%，CBF 在几乎每个时间步都在修正动作。但你细想，如果一个 episode 只有 9 步、0.17 秒，它根本连"走到目标"的机会都没有——它不是"走了很久但没到"，它是"还没开始走就被重置了"。

于是我加了 reset reason 指标，分别统计每次 reset 是哪种原因触发的。一统计就发现问题了——contact_force 大于 50 的 hard reset 占比远超预期。原来的逻辑对所有刚体都检查横向接触力，足端正常落地、和地面摩擦、初始化瞬间的冲击，都可能触发 reset。

修复方法两句话：一个是把 hard contact reset 收窄到 base 和 head 这些真正危险的部位，也就是 termination_contact_indices；另一个是加了 10 步的 warmup 期，初始化前几步只记录不重置。

修复后的冒烟测试——16 个环境 30 步——前几步的 done 数量为零，contact50 的 reset 也是零。这说明之前训练失败的首要原因不是算法，而是环境终止逻辑错误地切断了训练样本。从 success 等于零变成能够训练，这个转变靠的不是调网络参数，而是工程诊断。

第四个问题是 CBF 边界与碰撞阈值不一致，前面已经讲过了。

第五个问题是 Isaac Gym 在退出时的 segmentation fault。多次训练和评估结束时都出现 return code 139。但我检查后发现——checkpoint 已经正常保存，train_metrics.csv 已经正常写出，torch.load 可以正常读取，策略录像也可以加载模型运行。所以我判断这是 Isaac Gym 析构阶段的问题，而不是 PPO 更新失败或 Python 逻辑错误。记录但不影响训练。

这里我想分享一个核心的方法论认识。复杂 RL 任务中，如果你的 success 是零，不要直接去调网络、调学习率、调奖励权重。先看诊断指标链——episode length 是多少？如果很短，是哪种 reset 占主导？如果是 contact reset，是哪个部位触发的？一层一层追下去。诊断指标是把"训练失败"转化成一个"可解释的问题"的前提。这是本周学到的最重要的东西。

## 第九章：结果分析与策略行为诊断（3-4 分钟）

翻到结果分析这一页。

先看 model_500 的固定评估——40 个 episode，success 只有 40%，safe_success 只有 27.5%。更关键的是我通过视频发现了两个典型的行为问题。

第一个问题是目标点已经很近了但机器人绕着走，就是到了但停不下来、转圈。这说明近目标阶段缺少收敛约束——策略没有被教会"到了就停下"。

第二个问题是动态障碍物从右往左运动，机器人也往左躲，正好撞到障碍物未来位置。这是因为策略只看当前距离——"你离我 1 米，我往左走 0.5 米，安全距离够了"——但它忽略了障碍物也在往左走，0.5 秒之后你们会相遇。这就是没有速度感知的后果。

再看 model_400——这是奖励函数优化后的训练中间窗口。success 89.6%，safe_success 也是 89.6%，动态碰撞只有 0.0208，pass_behind_score 是正的。这里我要强调一下，这个数字是训练窗口指标，不是严格固定评估，所以不能把它当作最终结论。但它足以说明：这组 reward 和 CBF 边界对齐产生了一个明显更好的候选 checkpoint。10 个 episode 的录像里成功了 6 次，失败 4 次，而且动态碰撞只出现在一个 episode 里。

这说明近目标奖励、CBF 边界对齐、pass_behind 奖励这三个方向的改进是有效的。但 10 个 episode 仍有 4 次失败，策略行为还不够稳定。

分析两个残留问题。

第一个是训练后段退化。为什么 iter 400 到 iter 490 指标大幅下降？我目前的判断是多个奖励项之间存在竞争——策略一方面被近目标奖励牵引，另一方面也受动态避障、安全层修正、接触终止和 PPO 探索噪声的影响。训练后期可能从较优的行为漂移出去。后续需要降学习率、存更密的 checkpoint、观察 entropy 和 surrogate loss 来判断退化的根源。

第二个是安全层依赖。shield_intervention_rate 长期接近 0.99——这意味着 99% 的时间步里，实际执行动作都经过 CBF 修正，而不是 nominal policy 原样输出。策略可能学会"输出一个大致方向，CBF 会帮我调"的依赖行为。这会导致三个后果——到达效率低，因为 CBF 只保证安全不保证效率；目标附近绕远，因为目标推进可能被安全修正和局部障碍约束压制；以及动态让行方向不稳定，因为 CBF 不知道"从哪边绕更优"，它只知道"你不能往那边去"。

后续需要通过 u_bar_goal_angle 和 usafe_goal_angle 的分离分析，判断是 policy 学偏了还是 CBF 调过强了，然后针对性地修复。

## 第十章：阶段性认识与下一步计划（4-5 分钟）

最后一章，我总结本周形成的四个阶段性认识。

第一，动态避障的关键不是"障碍物会动"，而是"策略理解运动趋势"。把 moving actor 放进仿真只是第一步。真正决定性能的是观测、奖励和安全层是否共同编码了运动信息。

第二，安全层既是优势也是双刃剑。SEA-Nav 的 CBF 让训练早期不至于大量撞障碍，这是很强的优势。但当介入率达到 99% 时，策略会形成依赖——名义策略不再学习安全行为，而是把安全责任外包给了安全层。这会影响到达效率和让行方向稳定性。

第三，工程诊断指标的价值不低于最终成功率。第一次训练 success 等于零的时候，如果没有 reset reason 的统计，我很可能误判为算法失败然后去调各种超参数。正是诊断指标帮我定位到 contact reset 误触发，两步修复就解决了问题。对于一个复杂的 RL 系统，episode_length、reset_reason、collision_type、intervention_rate 这些诊断指标和最终成功率是同等重要的。

第四，当前路线有明确的升级空间。本周虽然没有引入 GNN 和 Transformer，但保留的 dynamic token 接口可以直接接 attention encoder；velocity-aware CBF 可以升级为 observation-conditioned safety filter；near-miss replay 可以扩展为 Reach-Avoid 恢复策略训练。本周的工作既是可训练的工程基座，也是后续研究的起点。

我还想单独强调一下本周的研究闭环。因为这个工作如果只看代码，会像是在调 reward；但从研究过程看，它其实是一个完整的假设验证过程。

第一步是文献归纳。我没有直接照搬某一篇论文，而是从 12 篇文献中归纳出四个共同维度：VO/TTC、CBF 安全层、Reach-Avoid 值网络和 GNN/Attention 交互建模。然后根据当前仓库的成熟度和调试难度，选择先落地前两个，再为后两个预留接口。

第二步是环境诊断。第一次训练 success 等于零时，我没有把它当成策略能力不足，而是先问"episode 有没有足够长"。这个问题带出了 reset reason，然后定位到 contact reset 误触发。这个过程说明，复杂 RL 的第一步不是调算法，而是保证训练样本有效。

第三步是行为诊断。model_500 的曲线并不能告诉我为什么视频里机器人绕远。只有看视频，才能把失败模式抽象成两个可修复假设：近目标缺少收敛信号，横穿障碍缺少 pass-behind 方向信号。奖励设计不是凭感觉加项，而是每一项对应一个具体的行为失败模式。

第四步是验证和反思。Run 3 的 model_400 验证了这些假设的一部分——success 和 safe_success 在训练窗口内显著提升，pass_behind_score 也变成正值。但 final checkpoint 又退化，说明机制有效但不稳定。这个结果不是失败，而是给出了下一阶段清晰的问题：要做固定评估、checkpoint selection 和单项消融。

所以我认为本周最重要的成果不是"某个指标提高了多少"，而是建立了一套可以持续迭代的研究方法：从文献提炼机制，从视频抽象失败模式，从指标定位根因，再用消融验证机制。

下一步计划分了八个步骤，从 A0 到 A8。核心思路是先稳定再扩展。A0 是做三个 checkpoint 的固定评估确认最佳模型。A1 是三个随机种子复现确认可重复性。A2 和 A3 分别做近目标奖励和 pass-behind 奖励的消融——每次只动一个权重，看行为的变化方向。A4 解决后段退化。等 Easy complex 稳定验收后再开 near-miss replay 和 Medium curriculum。长期来看可以引入 GNN、Reach-Avoid 和 observation-conditioned safety filter。

这就是我本周的全部工作。总结起来说，本周的主要贡献不是单个指标的提升，而是从文献理解、方案取舍、环境重构、安全层扩展、训练诊断、奖励函数定向修复到下一步消融计划，完成了一个完整的学术闭环。谢谢大家，请各位老师和同学提意见。

## 可能的 Q&A 准备

**Q: 为什么不一次性把 GNN 或 Transformer 加上？**
A: 这是一个工程方法论的选择。当前障碍物是轨迹驱动的，没有真实交互意图，引入交互建模是过度设计。而且复杂环境本身还没有稳定的训练基座，如果现在加新模块，出了问题很难区分是环境问题还是新模块问题。我选择先跑通基座，但保留扩展接口，后续可以很自然地接入。

**Q: 安全层依赖问题怎么解决？**
A: 可以增加 intervention_loss，惩罚 nominal policy 输出与 CBF 修正后动作的差异。或者逐渐降低 CBF 的干预强度作为 curriculum。或者让 alpha 参数也进入学习，使安全层本身变得更智能。这些都在下一阶段实验中。

**Q: 后段退化的原因是什么？有验证吗？**
A: 目前判断是多个 reward 项之间出现竞争。我会通过分析 entropy、surrogate_loss、各 reward 分量贡献的趋势来验证。如果确认是 reward 竞争导致的，可以通过降低后期 entropy_coef 或者调整 reward 权重来解决。

**Q: 跟 Agile But Safe 的区别是什么？**
A: Agile But Safe 用的是双策略加 Reach-Avoid 值网络，是一个更完整的框架。我本周选择了一条更渐进的路线——先把 SEA-Nav 现有的 CBF 安全层从静态升级为 velocity-aware。这比 Reach-Avoid 值网络的改动更小、更可控。Reach-Avoid 值网络是我后续计划中 A8 阶段的方向。

**Q: 目前的成功率 89.6% 是在什么条件下取得的？**
A: 需要诚实地说，这是训练窗口的指标，不是严格固定评估。下一步第一件事就是对 model_400 做 50 episode 的固定评估。而且这是 Easy difficulty——2 到 4 个低速障碍物。距离实际部署还有很大距离。
